*Working on one screen, without giving up the thing you need to see.*

`hfsgtfoomw` (the acronym is the name; you already know how to say it) is a
single-screen attention layer: one keystroke puts the thing you need to keep an
eye on into a small always-on-top window in the corner, and one keystroke takes
it away again. The window you are working in never loses focus, never gets
covered, and never gets resized out of your way.

== The problem

A second monitor is a workaround for three separate problems, and buying one
only solves the first:

. *Space contention.* Two things need to be visible at once -- the work, and a
  reference: a call, a build log, a dashboard, a doc, a chat.
. *Forced context switching.* Alt-tab is a full-precision action: you lose your
  place, your scroll position, and your train of thought, every time.
. *No second screen available.* Laptop on a train, hot desk, small desk, or an
  employer that issues one screen and no budget for two.

Picture-in-picture is the closest thing the desktop has to an answer, and it is
almost always the *wrong* picture-in-picture: video only, in one application,
on one platform, and it usually steals focus when you interact with it.

== What this will be

One control surface with the same behaviour everywhere:

* *One chord in, one chord out.* Idempotent. No menus, no window hunting.
* *Any source:* a native window, a screen region, a web page, a terminal pane,
  or a log stream.
* *Never steals keyboard focus.* Typing always lands in your main window. This
  is the "get out of my way" test, and most naive implementations fail it.
* *Deterministic geometry.* Same corner, same size, every time, across
  workspace switches and monitor hot-plug.
* *Degrades loudly.* If the platform cannot do the good version, it says which
  primitive is missing and falls back to the next best one. It never silently
  does nothing.

== Definition of done

The first release is done when all of these are true on the primary platform:

. From a normal single-window workspace, *one chord* makes a window of roughly
  480x270 appear in a chosen corner, showing live content from another source.
. It *never* takes keyboard focus; typing continues uninterrupted in the main
  window.
. One chord hides it; the chord is idempotent; state survives a restart of the
  overlay and, where the platform allows, of the session.
. Geometry does not drift across workspace switches, resolution changes or
  monitor hot-plug.
. Budgets: appears in under 100 ms, under 30 MB resident, under 1% idle CPU,
  no network egress, no telemetry.
. An unsupported platform produces a specific error naming the missing
  primitive, never a silent no-op.
. The feature degrades down a ladder rather than vanishing:
  overlay -> pinned floating window -> terminal popup -> printed instructions.

== How it is intended to work

Every desktop already has *some* of the primitives; none has the composition.
The plan is to compose them, per platform, and expose one behaviour:

[cols="1,2,2",options="header"]
|===
| Layer | Mechanism | What it gives you

| Overlay
| A top-layer always-on-top surface fed by screen capture (desktop portal /
  PipeWire where available), with no keyboard interactivity
| Live content from *any* window or region, no focus theft

| Pinned window
| The compositor's own float + pin + geometry rules
| Zero new dependencies; works on any window the compositor controls

| Terminal popup
| A multiplexer popup bound to one chord
| Reference and logs on machines where no GUI capture is permitted, including
  over SSH

| Instructions
| Printed, copy-pasteable setup for platforms this tool does not support
| Honest failure instead of a broken promise
|===

== Design principles

* *Interruption is the failure mode.* Every interaction is one chord; nothing
  opens a dialog at the moment you are trying to concentrate.
* *The overlay is furniture, not an application.* It has no taskbar entry, no
  focus, no notifications, and no title you have to read.
* *Nothing is captured without consent.* No screen content leaves the machine,
  ever; no network code ships in the first release.
* *Fail loudly, degrade gracefully.* An unsupported platform is a message, not a
  no-op.
* *Compose, don't reimplement.* If a compositor, portal or existing tool already
  does a layer well, wrap it -- and pin the version we tested.
